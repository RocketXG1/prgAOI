MANUAL TECNICO DEL MODULO objStepperAxis.py
Control orientado a objetos de ejes lineales con motores a pasos, señales STEP/DIR/ENABLE y generacion de pulsos mediante PIO en Raspberry Pi Pico/RP2040.

===============================================================================
1. TITULO DEL MANUAL
===============================================================================

Manual tecnico del archivo: objStepperAxis.py

Descripcion breve:
Este archivo implementa un modulo MicroPython para controlar ejes lineales de un sistema cartesiano X/Y/Z usando motores a pasos, drivers externos y una StateMachine PIO por eje. El modulo define una clase base comun para un eje y dos clases derivadas para calcular la conversion mecanica en sistemas de banda/polea o tornillo/husillo.

===============================================================================
2. INTRODUCCION
===============================================================================

El modulo objStepperAxis.py sirve para representar y controlar un eje lineal individual de una maquina cartesiana, por ejemplo los ejes X, Y o Z de una maquina tipo CNC, plotter, impresora 3D o sistema XYZ basado en Raspberry Pi Pico.

Su objetivo principal es abstraer el control electrico y mecanico de un motor a pasos en una interfaz orientada a objetos. En lugar de que el programa principal manipule directamente pines STEP, DIR y ENABLE, el usuario crea un objeto de eje y utiliza metodos como home(), move_to_mm(), move_relative_mm(), get_status() o stop().

Dentro del proyecto, este archivo pertenece al area de control de ejes y control de movimiento basico. Tambien pertenece al uso de PIO porque la generacion precisa de pulsos STEP se delega al periférico PIO del RP2040 mediante rp2.asm_pio y rp2.StateMachine.

El problema que resuelve dentro de un sistema XYZ con Raspberry Pi Pico es el siguiente:

  - Convertir posiciones en milimetros a pasos de motor.
  - Generar trenes de pulsos STEP con tiempo estable usando PIO.
  - Controlar direccion mediante el pin DIR.
  - Habilitar o deshabilitar el driver con ENABLE.
  - Ejecutar homing usando un sensor de referencia.
  - Mantener una posicion logica del eje.
  - Validar limites minimos y maximos de recorrido.
  - Reportar estado, posicion y errores.

Esta version trabaja con velocidad fija. No implementa aceleracion, desaceleracion, interpolacion entre varios ejes ni perfiles trapezoidales. Por lo tanto, es un controlador de eje individual, no un planificador de movimiento multieje avanzado.

===============================================================================
3. CONTEXTO GENERAL DEL PROYECTO
===============================================================================

El proyecto consiste en controlar motores a pasos de un sistema cartesiano X/Y/Z. En una maquina cartesiana, cada eje representa un grado de libertad lineal:

  - Eje X: desplazamiento horizontal.
  - Eje Y: desplazamiento longitudinal.
  - Eje Z: desplazamiento vertical.

El hardware esperado es una Raspberry Pi Pico o placa compatible con RP2040 ejecutando MicroPython. El RP2040 dispone de PIO, un subsistema programable capaz de generar señales con temporizacion mas estable que un bucle Python normal.

Los motores no se conectan directamente al RP2040. Se controlan mediante drivers externos como TB6600, TMC2209, A4988, DRV8825 u otros equivalentes. Estos drivers suelen recibir las siguientes señales:

  - STEP/PUL: cada pulso ordena un micro-paso o paso al driver.
  - DIR: define el sentido de giro del motor.
  - ENABLE: habilita o deshabilita la etapa de potencia del driver.

Relacion con otros modulos del proyecto:

  - objStepperAxis.py representa el nivel de eje individual.
  - Un modulo de mayor nivel, si existe, podria crear objetos X, Y y Z usando BeltStepperAxis o ScrewStepperAxis.
  - Un controlador de movimiento multieje podria coordinar varios objetos de este archivo para ejecutar trayectorias mas complejas.
  - Otros modulos del proyecto pueden encargarse de comunicacion serial, recetas, iluminacion, interfaz o secuencias de operacion.

Uso de PIO:

Este archivo usa PIO porque la generacion de pulsos STEP requiere una temporizacion relativamente precisa. Si se generaran pulsos desde MicroPython con sleep_us() o bucles normales, el jitter del interprete podria afectar la regularidad del movimiento. PIO permite que el tren de pulsos se ejecute en hardware mientras el codigo Python supervisa el estado general.

Tipo de modulo:

Este archivo no es un MotionController multieje. Controla pines directamente, pero solamente para un eje. Su responsabilidad es coordinar hardware, estado interno y conversion mecanica de un solo eje. Un controlador superior podria usar composicion para administrar varios ejes.

4. RESUMEN DEL ARCHIVO
===============================================================================

El archivo contiene:

  - 3 clases.
  - 6 constantes globales de estado publico.
  - 1 constante global asociada a temporizacion PIO.
  - 1 programa PIO para generar pulsos STEP.

Clases encontradas:

  1) StepperAxisBase
     Clase base que implementa la logica comun de control de un eje lineal.
     Administra pines, PIO, estado, homing, conversion mm/pasos, movimientos
     absolutos y relativos, errores y parada.

  2) BeltStepperAxis
     Clase derivada para ejes accionados por banda y polea. Calcula steps_per_mm
     usando pasos del motor, microsteps, dientes de polea y pitch de la banda.

  3) ScrewStepperAxis
     Clase derivada para ejes accionados por tornillo/husillo. Calcula
     steps_per_mm usando pasos del motor, microsteps y avance del tornillo.

Constantes globales:

  - STATE_NOT_HOMED = "NOT_HOMED"
  - STATE_IDLE      = "IDLE"
  - STATE_MOVING    = "MOVING"
  - STATE_HOMING    = "HOMING"
  - STATE_ERROR     = "ERROR"
  - STATE_STOPPED   = "STOPPED"
  - PIO_CYCLES_PER_STEP = 4

Programa PIO:

  - _step_pulse_program()
    Programa ensamblador PIO que recibe una cantidad de pasos por FIFO y genera
    pulsos en el pin STEP.

===============================================================================
5. CANTIDAD DE CLASES
===============================================================================

Numero total de clases: 3

1) StepperAxisBase
   Responsabilidad:
     Implementar la funcionalidad comun de un eje lineal con motor a pasos:
     inicializacion de hardware, validacion, movimiento, homing, conversion de
     unidades, estado y errores.

   Relacion:
     Es clase base. No se deberia instanciar directamente porque el metodo
     _calculate_steps_per_mm() no esta implementado y lanza NotImplementedError.

2) BeltStepperAxis
   Responsabilidad:
     Representar un eje lineal con transmision por banda y polea.

   Relacion:
     Hereda de StepperAxisBase. Sobrescribe _calculate_steps_per_mm(). Antes de
     llamar al constructor base, valida pulley_teeth y belt_pitch_mm.

3) ScrewStepperAxis
   Responsabilidad:
     Representar un eje lineal con transmision por tornillo/husillo.

   Relacion:
     Hereda de StepperAxisBase. Sobrescribe _calculate_steps_per_mm(). Antes de
     llamar al constructor base, valida screw_lead_mm.

Relacion general entre clases:

  StepperAxisBase contiene la logica general.
  BeltStepperAxis y ScrewStepperAxis reutilizan esa logica y solamente cambian
  el calculo mecanico de steps_per_mm.

6. CANTIDAD DE VARIABLES Y ATRIBUTOS PRINCIPALES

6.1 Atributos principales de StepperAxisBase
--------------------------------------------

A) Variables de identificacion y configuracion:

  - name
    Nombre logico del eje. Ejemplos: "X", "Y", "Z".

  - step_pin_number
    Numero GPIO usado para la señal STEP.

  - dir_pin_number
    Numero GPIO usado para la señal DIR.

  - enable_pin_number
    Numero GPIO usado para la señal ENABLE.

  - sm_id
    Identificador de la StateMachine PIO usada por este eje.

  - motor_steps_per_rev
    Pasos completos del motor por revolucion. Valor tipico: 200 para motores de
    1.8 grados por paso.

  - microsteps
    Microstepping configurado en el driver. Valores tipicos: 1, 2, 4, 8, 16,
    32. Debe coincidir con los DIP switches o configuracion del driver.

  - steps_per_mm
    Conversion final entre milimetros y pasos. Se calcula automaticamente en
    las clases derivadas.

B) Variables de limite y movimiento:

  - speed_mm_s
    Velocidad normal de movimiento en mm/s.

  - max_speed_mm_s
    Velocidad maxima permitida en mm/s. Se usa para validar speed_mm_s y
    home_speed_mm_s.

  - min_position_mm
    Limite minimo permitido del eje en milimetros.

  - max_position_mm
    Limite maximo permitido del eje en milimetros.

  - target_position_mm
    Objetivo actual en milimetros. Puede ser None si no hay objetivo cargado.

  - target_position_steps
    Objetivo actual en pasos. Puede ser None si no hay objetivo cargado.

  - current_position_mm
    Posicion logica actual en milimetros.

  - current_position_steps
    Posicion logica actual en pasos.

  - _move_start_position_mm
    Posicion de inicio del movimiento actual.

  - _move_delta_steps
    Cantidad de pasos a ejecutar en el movimiento actual.

  - _move_direction_sign
    Sentido logico del movimiento actual. Usa 1 para positivo y -1 para
    negativo.

  - _move_done
    Bandera interna que indica si el movimiento PIO termino.

C) Variables de homing:

  - home_pin_number
    Numero GPIO del sensor HOME. Existe solo si se configuro home_pin.

  - home_pin
    Objeto Pin configurado como entrada con pull-up. Si no hay sensor, es None.

  - home_direction
    Direccion en la que se busca el sensor HOME. Se normaliza a -1 o 1.

  - home_speed_mm_s
    Velocidad de busqueda de HOME.

  - home_backoff_mm
    Distancia de retirada despues de tocar el sensor HOME.

  - home_active_low
    Define si el sensor HOME se considera activo cuando el pin lee 0.

  - is_homed_flag
    Indica si el eje ya fue referenciado correctamente.

D) Variables de hardware:

  - step_pin
    Objeto machine.Pin de salida para STEP.

  - dir_pin
    Objeto machine.Pin de salida para DIR.

  - enable_pin
    Objeto machine.Pin de salida para ENABLE.

  - sm
    Objeto rp2.StateMachine que ejecuta el programa PIO.

  - enable_active_low
    Define la polaridad del pin ENABLE. Si es True, ENABLE se activa escribiendo
    0.

  - invert_direction
    Invierte la polaridad logica del pin DIR si el motor se mueve al reves.

  - _enabled
    Bandera interna que indica si el driver fue habilitado por el objeto.

E) Variables de estado y error:

  - state
    Estado publico del eje. Puede ser NOT_HOMED, IDLE, MOVING, HOMING, ERROR o
    STOPPED.

  - error
    Texto con el ultimo error registrado. Es None cuando no hay error activo.

6.2 Atributos principales de BeltStepperAxis
--------------------------------------------

A) Variables de configuracion mecanica:

  - pulley_teeth
    Numero de dientes de la polea motriz. Valor comun en impresoras tipo Ender:
    20 dientes.

  - belt_pitch_mm
    Paso de la banda en mm por diente. Valor comun para correa GT2: 2.0 mm.

B) Variables heredadas:

  Hereda todos los atributos de StepperAxisBase, incluyendo pines, limites,
  posicion, estado, error, homing y PIO.

6.3 Atributos principales de ScrewStepperAxis
---------------------------------------------

A) Variables de configuracion mecanica:

  - screw_lead_mm
    Avance lineal del tornillo por una revolucion completa. En un eje Z tipo
    Ender 3 V2, un valor tipico es 8.0 mm por revolucion para un husillo T8 de
    cuatro entradas.

B) Variables heredadas:

  Hereda todos los atributos de StepperAxisBase.

  - name
    Tipo esperado: str o valor convertible a str.
    Ejemplo: "X", "Y", "Z".

  - step_pin
    Tipo esperado: int o convertible a int.
    Ejemplo: 2.

  - dir_pin
    Tipo esperado: int o convertible a int.
    Ejemplo: 3.

  - enable_pin
    Tipo esperado: int o convertible a int.
    Ejemplo: 4.

    Valor por defecto: 200.

  - microsteps
    Tipo: int.

    Debe ser mayor que 0 y menor o igual a max_speed_mm_s.

  - max_speed_mm_s
    Tipo: float.
    Valor por defecto: 100.0.
    Debe ser mayor que 0.

  - min_position_mm
    Tipo: float.
    Valor por defecto: 0.0.

  - max_position_mm
    Tipo: float.
    Valor por defecto: 100.0.
    Debe ser mayor que min_position_mm.

  - home_pin
    Tipo: int o None.
    Valor por defecto: None.
    Si es None, home() no podra ejecutarse correctamente.

  - home_direction
    Tipo: int.
    Valor por defecto: -1.
    Si es negativo se convierte a -1; si es cero o positivo se convierte a 1.

  - home_speed_mm_s
    Tipo: float.
    Valor por defecto: 5.0.
    Debe ser mayor que 0 y menor o igual a max_speed_mm_s.

  - home_backoff_mm
    Tipo: float.
    Valor por defecto: 2.0.
    Internamente se usa como valor absoluto.

  - invert_direction
    Tipo: bool.
    Valor por defecto: False.
    Se usa para invertir el sentido del eje sin cambiar cableado.

  - enable_active_low
    Tipo: bool.
    Valor por defecto: True.
    True significa que el driver se habilita escribiendo 0 en ENABLE.

  - home_active_low
    Tipo: bool.
    Valor por defecto: True.

8. SALIDAS DEL MODULO
===============================================================================

El modulo produce salidas de tres tipos:

  1) Salidas fisicas de hardware:
     - Pulsos STEP generados por PIO.
     - Nivel logico DIR segun direccion.
     - Nivel logico ENABLE segun habilitacion.

  2) Retornos de metodos:
     - Booleanos True/False para indicar exito o fallo.
     - Diccionarios de estado.
     - Posiciones en milimetros.
     - Estados de texto.

  3) Cambios de estado interno:
     - state
     - error
     - current_position_mm
     - current_position_steps
     - target_position_mm
     - target_position_steps
     - is_homed_flag
     - _enabled

Metodos y retornos importantes:

  - get_position()
    Devuelve current_position_mm como numero float.

  - get_status()
    Devuelve un diccionario con campos:
      name, state, error, position_mm, position_steps, target_position_mm,
      target_position_steps, homed, enabled, steps_per_mm, speed_mm_s,
      max_speed_mm_s, min_position_mm, max_position_mm, moving, pio_freq,
      pio_cycles_per_step.

  - is_home_active()
    Devuelve True si el sensor HOME esta activo. Devuelve False si no hay
    home_pin configurado o si el sensor no esta activo.

  - set_speed_mm_s()
    Devuelve True si la velocidad fue aceptada. Devuelve False si esta fuera de
    rango o si se intenta cambiar durante movimiento/homing.

  - start_move_to_mm()
    Devuelve True si el movimiento absoluto se inicio o si el eje ya estaba en
    esa posicion. Devuelve False si hay error.

  - move_to_mm()
    Devuelve True si el movimiento bloqueante finaliza en IDLE. Devuelve False
    si no pudo iniciar o si no queda en IDLE.

  - start_move_relative_mm()
    Devuelve lo mismo que start_move_to_mm(), pero calculando primero el destino
    como posicion actual + distancia.

  - move_relative_mm()
    Devuelve True si el movimiento relativo bloqueante termina correctamente.

  - wait_until_done()
    Devuelve el estado final del eje despues de esperar. Normalmente devuelve
    IDLE si el movimiento termino bien.

  - home()
    Devuelve True si el homing se completo y la posicion quedo en 0 mm. Devuelve
    False si no hay sensor, si no detecta HOME o si hay condiciones invalidas.

  - stop()
    Devuelve True despues de detener PIO, deshabilitar el driver e invalidar el
    home.

Interpretacion de estados:

  - NOT_HOMED:
    El eje no tiene referencia valida. No se permiten movimientos normales.

  - IDLE:
    El eje esta quieto y listo. Si homed es True, puede moverse.

  - MOVING:
    Hay un movimiento normal en progreso.

  - HOMING:
    Se esta ejecutando la busqueda de HOME.

  - ERROR:
    Ocurrio un error. Revisar el campo error.

  - STOPPED:
    Se llamo a stop(). La posicion ya no debe considerarse confiable hasta
    repetir home().

Nota sobre is_busy() e is_homed():

El archivo no implementa metodos llamados is_busy() ni is_homed(). Sin embargo,
la misma informacion se obtiene asi:

  - Eje ocupado: get_status()["moving"] o state == STATE_MOVING.
  - Eje referenciado: get_status()["homed"] o is_homed_flag.

9.1 StepperAxisBase
-------------------

Proposito:
  Proporcionar la implementacion comun para controlar un eje lineal con motor a
  pasos, driver externo y PIO.

Cuando se debe usar:
  Se debe usar como clase base para crear tipos concretos de ejes. No se debe
  crear directamente porque no sabe calcular steps_per_mm sin conocer el tipo de

Que objetos representa:
  Representa un eje lineal generico con:
    - motor a pasos,
    - driver externo,
    - pin STEP,
    - pin DIR,
    - pin ENABLE,
    - sensor HOME opcional,
    - limites de recorrido,
    - posicion logica en mm y pasos.

Parametros del constructor:
  Ver seccion 7.2. Incluyen name, step_pin, dir_pin, enable_pin, sm_id,
  parametros de motor, microsteps, velocidad, limites, homing, polaridades e
  inversion de direccion.

Atributos internos principales:
  - name
  - step_pin, dir_pin, enable_pin
  - home_pin
  - sm
  - steps_per_mm
  - current_position_mm, current_position_steps
  - target_position_mm, target_position_steps
  - state
  - error
  - is_homed_flag
  - _move_done
  - _enabled

Metodos principales:
  - enable()
  - disable()

  - start_move_to_mm()
  - move_to_mm()
  - start_move_relative_mm()
  - move_relative_mm()
  - wait_until_done()
  - stop()
  - get_status()
  - get_position()

Metodos secundarios o internos:
  - _calculate_steps_per_mm()
  - _on_pio_done()
  - _set_error()
  - _clear_error()
  - _speed_to_pio_freq()
  - _mm_to_steps()
  - _steps_to_mm()
  - _validate_target()
  - _write_direction()
  - is_home_active()
  - set_speed_mm_s()
  - _run_steps_blocking()
  - _mark_internal_move_done()

Flujo tipico de uso:

  1) Crear un objeto derivado, por ejemplo BeltStepperAxis o ScrewStepperAxis.
  2) Verificar configuracion de pines, limites y sensor HOME.
  3) Ejecutar home().
  4) Si home() devuelve True, usar move_to_mm() o move_relative_mm().
  5) Consultar get_status() para verificar posicion y estado.
  6) Usar stop() ante una condicion anormal o emergencia local.

Errores comunes:

  - Intentar crear StepperAxisBase directamente.
  - No configurar home_pin y luego llamar home().
  - Intentar mover sin haber hecho home().
  - Usar una velocidad mayor que max_speed_mm_s.
  - Definir limites invertidos: min_position_mm >= max_position_mm.
  - Reutilizar el mismo sm_id para varios ejes activos.
  - Configurar mal enable_active_low o home_active_low.

Recomendaciones de uso:

  - Usar clases derivadas concretas.
  - Empezar con velocidades bajas.
  - Probar primero sin motor o con driver deshabilitado si se desea validar
    señales.
  - Confirmar la polaridad del sensor HOME.
  - Hacer home() despues de cada stop() o perdida de pasos.

9.2 BeltStepperAxis
-------------------

Proposito:
  Controlar un eje lineal movido por banda y polea.

Cuando se debe usar:
  En ejes como X o Y de impresoras 3D tipo Ender, plotters o sistemas XY que
  usan correa dentada GT2 y polea motriz.

Que objetos representa:
  Un eje fisico donde una revolucion del motor desplaza la correa una distancia:

    distancia_por_rev = pulley_teeth * belt_pitch_mm

Parametros del constructor:

  - pulley_teeth:
    Numero de dientes de la polea. Debe ser mayor que 0.

  - belt_pitch_mm:
    Separacion entre dientes de la correa. Debe ser mayor que 0.

  - *args, **kwargs:
    Parametros heredados de StepperAxisBase.

Atributos internos principales:

  - pulley_teeth
  - belt_pitch_mm
  - todos los atributos heredados de StepperAxisBase

Metodos principales:

  - _calculate_steps_per_mm()
    Calcula la resolucion lineal del eje.

  - Todos los metodos heredados de StepperAxisBase.

Formula:

  steps_per_mm = (motor_steps_per_rev * microsteps) /
                 (pulley_teeth * belt_pitch_mm)

Ejemplo:

  motor_steps_per_rev = 200
  microsteps = 16
  pulley_teeth = 20
  belt_pitch_mm = 2.0

  steps_per_mm = 3200 / 40 = 80 steps/mm

Flujo tipico de uso:

  1) Crear el objeto BeltStepperAxis para X o Y.
  2) Ejecutar home().
  3) Ordenar movimientos absolutos o relativos.
  4) Consultar estado.

Errores comunes:

  - Configurar pulley_teeth incorrecto.
  - Configurar belt_pitch_mm diferente al real.
  - Cambiar microsteps en el driver sin cambiar el parametro microsteps.

Recomendaciones de uso:

  - Para correas GT2, usar belt_pitch_mm = 2.0.
  - Para poleas comunes de impresora 3D, revisar si son 16 o 20 dientes.
  - Verificar desplazamiento real con una regla o calibrador.

9.3 ScrewStepperAxis
--------------------

Proposito:
  Controlar un eje lineal movido por tornillo, husillo o varilla roscada.

Cuando se debe usar:
  En ejes Z o mecanismos de elevacion donde el motor gira un tornillo y la
  tuerca convierte giro en desplazamiento lineal.

Que objetos representa:
  Un eje fisico donde una revolucion del motor desplaza el carro una distancia
  igual a screw_lead_mm.

Parametros del constructor:

  - screw_lead_mm:
    Avance lineal por vuelta del tornillo. Debe ser mayor que 0.

  - *args, **kwargs:
    Parametros heredados de StepperAxisBase.

Atributos internos principales:

  - screw_lead_mm
  - todos los atributos heredados de StepperAxisBase

Metodos principales:

  - _calculate_steps_per_mm()
    Calcula la resolucion lineal del eje.

  - Todos los metodos heredados de StepperAxisBase.

Formula:

  steps_per_mm = (motor_steps_per_rev * microsteps) / screw_lead_mm

Ejemplo:

  motor_steps_per_rev = 200
  microsteps = 16
  screw_lead_mm = 8.0

  steps_per_mm = 3200 / 8 = 400 steps/mm

Flujo tipico de uso:

  1) Crear el objeto ScrewStepperAxis para Z.
  2) Ejecutar home().
  3) Mover a alturas absolutas con move_to_mm().
  4) Hacer ajustes pequenos con move_relative_mm().

Errores comunes:

  - Confundir paso del tornillo con avance.
  - Usar screw_lead_mm incorrecto en tornillos de varias entradas.
  - Mover Z demasiado rapido y perder pasos.

Recomendaciones de uso:

  - Empezar Z con velocidades bajas.
  - Confirmar el avance real del husillo.
  - Rehacer home despues de cualquier choque mecanico o stop().

10.1 _step_pulse_program()
--------------------------

Clase:
  No pertenece a una clase. Es un programa PIO global decorado con rp2.asm_pio.

Proposito:
  Generar una cantidad determinada de pulsos STEP en el pin configurado como
  set_base de la StateMachine.

Entradas:
  - Recibe por FIFO un valor entero equivalente a steps - 1.

Salidas/retorno:
  - No devuelve valor Python.
  - Genera pulsos fisicos en el pin STEP.
  - Lanza una interrupcion PIO relativa al finalizar.

Efectos internos:
  - Carga OSR en X.
  - Repite set alto, nop, set bajo y salto con decremento.

Bloqueante:
  - No bloquea al codigo Python una vez iniciada la StateMachine.

Dependencias:
  - Es usado por rp2.StateMachine en StepperAxisBase.

Posibles errores:
  - Si se envia un valor incorrecto al FIFO, la cantidad de pulsos no coincide.
  - El codigo espera que Python envie total_steps - 1.

10.2 StepperAxisBase.__init__()
-------------------------------

Proposito:
  Inicializar configuracion, validar parametros, crear pines, inicializar PIO,
  definir estado inicial y preparar la StateMachine.

Entradas:
  Todos los parametros indicados en la seccion 7.2.

Salidas/retorno:
  - No devuelve valor.
  - Puede lanzar ValueError si los parametros son invalidos.

Efectos internos:
  - Convierte tipos.
  - Calcula steps_per_mm llamando _calculate_steps_per_mm().
  - Valida velocidades, microsteps, limites y conversion.

  - Inicializa estado NOT_HOMED.

  - Crea rp2.StateMachine.

Bloqueante:

Dependencias:

===============================================================================
11. EXPLICACION DEL FLUJO INTERNO
===============================================================================

11.1 Inicializacion
-------------------

1) El usuario crea BeltStepperAxis o ScrewStepperAxis.
2) La clase derivada valida sus parametros mecanicos propios:
   - pulley_teeth y belt_pitch_mm en banda.
   - screw_lead_mm en tornillo.
3) La clase derivada llama StepperAxisBase.__init__().
4) La clase base convierte tipos y normaliza valores.
5) Se calcula steps_per_mm llamando _calculate_steps_per_mm().
6) Se validan parametros importantes:
   - steps_per_mm > 0
   - motor_steps_per_rev > 0
   - microsteps > 0
   - max_speed_mm_s > 0
   - speed_mm_s dentro de rango
   - home_speed_mm_s dentro de rango
   - min_position_mm < max_position_mm
7) Se crean objetos Pin para STEP, DIR y ENABLE.
8) Si se entrego home_pin, se crea como entrada con PULL_UP.
9) Se inicializan variables de posicion, objetivo, estado y error.
10) Se pone STEP en bajo.
11) Se deshabilita el driver.
12) Se crea rp2.StateMachine con _step_pulse_program().
13) Se registra el callback _on_pio_done().
14) La StateMachine queda inactiva.

11.2 Calculo de steps_per_mm
----------------------------

El modulo debe saber cuantos pulsos STEP equivalen a 1 mm de desplazamiento.

Para banda:

  steps_per_mm = (motor_steps_per_rev * microsteps) /
                 (pulley_teeth * belt_pitch_mm)

Para tornillo:

  steps_per_mm = (motor_steps_per_rev * microsteps) /
                 screw_lead_mm

Este valor afecta:

  - conversion de mm a pasos,
  - calculo de frecuencia PIO,
  - precision de posicion,
  - distancia real recorrida.

11.3 Home
---------

El metodo home() hace una rutina de referenciacion:

1) Verifica que exista home_pin.
2) Verifica que el eje no este en movimiento normal.
3) Limpia errores previos.
4) Cambia el estado a HOMING.
5) Marca is_homed_flag = False.
6) Habilita el driver.
7) Calcula backoff_steps a partir de home_backoff_mm.
8) Si el sensor ya esta activo, se mueve en sentido contrario para liberarlo.
9) Calcula el recorrido maximo de busqueda:

     travel_mm = max_position_mm - min_position_mm + home_backoff_mm

10) Busca el sensor en la direccion home_direction por bloques de 0.25 mm.
11) Despues de cada bloque consulta is_home_active().
12) Si no detecta HOME dentro del recorrido maximo, entra en ERROR.
13) Si detecta HOME, se retira home_backoff_mm.
14) Hace una segunda aproximacion lenta a la mitad de home_speed_mm_s.
15) En la segunda aproximacion usa bloques de 0.05 mm.
16) Si vuelve a detectar HOME, define:

     current_position_mm = 0.0
     current_position_steps = 0
     target_position_mm = 0.0
     target_position_steps = 0
     is_homed_flag = True
     state = IDLE

11.4 Movimiento absoluto
------------------------

El metodo start_move_to_mm(target_mm) inicia un movimiento no bloqueante:

1) Verifica que el eje no este en MOVING ni HOMING.
2) Verifica que el eje tenga home.
3) Valida que target_mm este dentro de limites.
4) Convierte target_mm a target_steps.
5) Calcula delta_steps = target_steps - current_position_steps.
6) Si delta_steps es 0, actualiza objetivo y queda en IDLE.
7) Si hay movimiento:
   - limpia error,
   - guarda posicion inicial,
   - guarda cantidad absoluta de pasos,
   - define direccion,
   - guarda objetivo en pasos y mm,
   - marca _move_done = False,
   - cambia state = MOVING.
8) Habilita el driver.
9) Escribe DIR.
10) Reinicializa la StateMachine con la frecuencia correspondiente a speed_mm_s.
11) Activa la StateMachine.
12) Envia _move_delta_steps - 1 por FIFO.
13) El PIO genera pulsos.
14) Al terminar, el callback _on_pio_done() consolida posicion y cambia state a
    IDLE.

11.5 Movimiento relativo
------------------------

El movimiento relativo se implementa reutilizando el movimiento absoluto:

  start_move_relative_mm(distance_mm)
      target = current_position_mm + distance_mm
      start_move_to_mm(target)

  move_relative_mm(distance_mm)
      start_move_relative_mm(distance_mm)
      wait_until_done()

11.6 Activacion del PIO
-----------------------

Antes de cada movimiento normal o interno:

1) sm.active(0) detiene la StateMachine.
2) sm.init(...) carga el programa PIO y frecuencia.
3) sm.irq(...) instala callback.
4) sm.active(1) activa la StateMachine.
5) sm.put(total_steps - 1) envia la cantidad de pulsos menos uno.

La frecuencia se calcula con:

  pio_freq = speed_mm_s * steps_per_mm * PIO_CYCLES_PER_STEP

11.7 Actualizacion de estado
----------------------------

Durante movimiento normal:

  - state = MOVING
  - _move_done = False

Al finalizar PIO:

  - _move_done = True
  - current_position_steps = target_position_steps
  - current_position_mm = target_position_mm
  - state = IDLE si homed es True

Durante home:

  - state = HOMING
  - is_homed_flag = False

Al finalizar home correctamente:

  - current_position_mm = 0
  - current_position_steps = 0
  - target_position_mm = 0
  - target_position_steps = 0
  - is_homed_flag = True
  - state = IDLE

11.8 Stop
---------

stop() detiene el eje localmente:

1) Desactiva la StateMachine.
2) Deshabilita el driver.
3) Marca _move_done = True.
4) Invalida is_homed_flag.
5) Cambia state a STOPPED.
6) Registra error indicando que se requiere home nuevamente.

Despues de stop(), la posicion no debe considerarse confiable porque el eje pudo
haber quedado entre pasos o haber perdido referencia mecanica.

11.9 Perfil trapezoidal y sincronizacion avanzada
-------------------------------------------------

Este modulo no calcula perfil trapezoidal. No hay segmentos de aceleracion,
velocidad constante y desaceleracion. Tampoco calcula tiempo minimo ni sincroniza
varios ejes a un tiempo comun.

La velocidad es fija durante todo el movimiento. Esto simplifica el codigo, pero
puede producir arranques y paradas bruscas si se usan velocidades altas.

          |
          +--> _validate_target(target_mm)
          |
          +--> _mm_to_steps(target_mm)
          |
          +--> _steps_to_mm(target_steps)
          |
          +--> enable()
          |
          +--> _write_direction(signo)
          |
          +--> _speed_to_pio_freq(speed_mm_s)
          |
          +--> sm.init(_step_pulse_program)
          |
          +--> sm.put(delta_steps - 1)
          |
          v
  _step_pulse_program() ejecuta pulsos STEP
          |
          v
  _on_pio_done()
          |
          v
  actualiza posicion y state

Movimiento absoluto bloqueante:

  move_to_mm(target_mm)
          |
          v
  start_move_to_mm(target_mm)
          |
          v
  wait_until_done()

Movimiento relativo:

  move_relative_mm(distance_mm)
          |
          v
  start_move_relative_mm(distance_mm)
          |
          v
  start_move_to_mm(current_position_mm + distance_mm)
          |
          v
  wait_until_done()

Homing:

  home()
     |
     +--> is_home_active()
     |
     +--> _mm_to_steps(home_backoff_mm)
     |
     +--> _run_steps_blocking(...)
     |          |
     |          +--> enable()
     |          +--> _write_direction()
     |          +--> _speed_to_pio_freq()
     |          +--> sm.put(steps - 1)
     |          +--> _mark_internal_move_done()
     |
     +--> is_home_active() repetidamente
     |
     v
  fija posicion logica en 0 mm

Parada:

  stop()
    |
    +--> sm.active(0)
    +--> disable()
    +--> invalida home
    +--> state = STOPPED

15. EXPLICACION DE MOVIMIENTO ABSOLUTO Y RELATIVO
===============================================================================

Movimiento absoluto:

Un movimiento absoluto usa como referencia el cero de maquina definido por home().
El valor indicado es una coordenada final, no una distancia a sumar.

Ejemplo:

  Posicion inicial despues de home: 0 mm

  move_to_mm(150)

  Resultado:
    El eje va a la coordenada 150 mm.

  Luego:

  move_to_mm(70)

  Resultado:
    El eje no avanza 70 mm mas. El eje regresa desde 150 mm hasta la coordenada
    absoluta 70 mm. El desplazamiento real es -80 mm.

Movimiento relativo:

Un movimiento relativo suma o resta una distancia a la posicion actual.

Ejemplo:

  Posicion actual: 70 mm

  move_relative_mm(70)

  Resultado:
    El objetivo se calcula como 70 + 70 = 140 mm.
    El eje avanza 70 mm desde donde esta.

Otro ejemplo:

  Posicion actual: 140 mm

  move_relative_mm(-20)

  Resultado:
    El objetivo se calcula como 140 - 20 = 120 mm.
    El eje retrocede 20 mm.

Diferencia conceptual:

  - move_to_mm(70) significa "ir a la coordenada 70 mm".
  - move_relative_mm(70) significa "moverse 70 mm desde la posicion actual".

===============================================================================
16. MANEJO DE ERRORES
===============================================================================

El modulo maneja errores principalmente con _set_error(). Cuando ocurre un error:

  - error guarda un mensaje descriptivo.
  - state cambia a ERROR.
  - _move_done cambia a True.
  - El metodo normalmente devuelve False.

Errores posibles:

16.1 Eje sin HOME
-----------------

Causa:
  Se intenta mover con start_move_to_mm(), move_to_mm(), start_move_relative_mm()
  o move_relative_mm() antes de ejecutar home() correctamente.

Deteccion:
  - El metodo devuelve False.
  - get_status()["state"] devuelve "ERROR".
  - get_status()["error"] indica "El eje requiere home antes de mover".

Correccion:
  - Configurar correctamente home_pin.
  - Ejecutar home().
  - Verificar que home() devuelva True.

16.2 Objetivo fuera de limite
-----------------------------

Causa:
  target_mm es menor que min_position_mm o mayor que max_position_mm.

Deteccion:
  - start_move_to_mm() devuelve False.
  - error contiene un mensaje con el destino y limites validos.

Correccion:
  - Ajustar el objetivo.
  - Revisar min_position_mm y max_position_mm.
  - Confirmar que el cero HOME sea correcto.

16.3 Eje ocupado
----------------

Causa:
  Se intenta iniciar un movimiento mientras state es MOVING o HOMING.

Deteccion:
  - start_move_to_mm() devuelve False con "El eje ya esta en movimiento".
  - set_speed_mm_s() devuelve False si se intenta cambiar velocidad durante
    movimiento u homing.

Correccion:
  - Esperar con wait_until_done().
  - Consultar get_status()["moving"].
  - No enviar ordenes simultaneas al mismo eje.

16.4 Falla de sensor HOME
-------------------------

Causa:
  El sensor no se activa durante la busqueda, esta desconectado, tiene polaridad
  incorrecta o el eje se mueve en direccion opuesta.

Deteccion:
  - home() devuelve False.
  - error puede ser:
      "HOME no detectado dentro del recorrido permitido"
      "HOME no detectado en segunda aproximacion"

Correccion:
  - Revisar cableado del sensor.
  - Probar is_home_active() manualmente.
  - Cambiar home_active_low si la logica esta invertida.
  - Cambiar home_direction si busca en el sentido incorrecto.
  - Aumentar limites solo si el recorrido fisico lo permite.

16.5 No hay home_pin configurado
--------------------------------

Causa:
  Se llama home() con home_pin = None.

Deteccion:
  - home() devuelve False.
  - error indica "No hay home_pin configurado".

Correccion:
  - Pasar home_pin al crear el eje.
  - Si el sistema no tiene sensor, se requeriria agregar un metodo externo de
    referencia manual, pero no existe en este archivo.

16.6 Parametros invalidos
-------------------------

Causa:
  Valores invalidos en el constructor:

  - steps_per_mm <= 0
  - motor_steps_per_rev <= 0
  - microsteps <= 0
  - max_speed_mm_s <= 0
  - speed_mm_s <= 0
  - speed_mm_s > max_speed_mm_s
  - home_speed_mm_s <= 0
  - home_speed_mm_s > max_speed_mm_s
  - min_position_mm >= max_position_mm
  - pulley_teeth <= 0
  - belt_pitch_mm <= 0
  - screw_lead_mm <= 0

Deteccion:
  - Se lanza ValueError durante la construccion del objeto.

Correccion:
  - Revisar valores de configuracion.
  - Usar valores fisicos reales y positivos.

16.7 Movimiento detenido
------------------------

Causa:
  Se llama stop().

Deteccion:
  - state = STOPPED.
  - error = "Eje detenido; se requiere home nuevamente".
  - homed = False.

Correccion:
  - Verificar causa de la parada.
  - Reposicionar mecanicamente si es necesario.
  - Ejecutar home() antes de nuevos movimientos normales.

16.8 Posicion no confiable despues de STOP
------------------------------------------

Causa:
  Al detener PIO abruptamente, el eje puede quedar en una posicion no confirmada.
  Ademas, el driver se deshabilita y el motor puede perder torque.

Deteccion:
  - is_homed_flag = False.
  - state = STOPPED.

Correccion:
  - No confiar en current_position_mm despues de stop().
  - Ejecutar home() nuevamente.

16.9 Direccion invertida
------------------------

Causa:
  El eje se mueve en sentido contrario al esperado.

Deteccion:
  - Durante pruebas, un movimiento positivo reduce la coordenada fisica o se
    aleja del sentido esperado.

Correccion:
  - Cambiar invert_direction.
  - Alternativamente cambiar cableado de una bobina del motor, pero es mas limpio
    ajustar invert_direction si el hardware esta correcto.

16.10 Polaridad ENABLE incorrecta
---------------------------------

Causa:
  enable_active_low no coincide con el driver.

Deteccion:
  - El motor no se energiza al llamar enable().
  - El driver queda habilitado cuando deberia estar deshabilitado.

Correccion:
  - Cambiar enable_active_low.
  - Revisar documentacion del driver.

===============================================================================
17. RECOMENDACIONES DE USO
===============================================================================

Buenas practicas generales:

  1) Verificar alimentacion del driver antes de conectar el motor.
  2) Confirmar GND comun entre Raspberry Pi Pico y driver.
  3) Verificar con multimetro o instrumento que STEP, DIR y ENABLE llegan al
     driver.
  4) Configurar microsteps en el driver y en el codigo con el mismo valor.
  5) Empezar con speed_mm_s bajo, por ejemplo 5 a 20 mm/s segun el mecanismo.
  6) Usar home_speed_mm_s bajo, por ejemplo 2 a 5 mm/s al inicio.
  7) Probar un eje a la vez.
  8) Probar primero movimientos cortos, por ejemplo 1 mm, 5 mm y 10 mm.
  9) No usar velocidades altas hasta confirmar que no hay perdida de pasos.
  10) Usar limites conservadores al principio.

Orden recomendado de pruebas:

  1) Crear el objeto con pines y parametros mecanicos.
  2) Llamar get_status() para revisar configuracion.
  3) Probar enable() y disable().
  4) Probar is_home_active() presionando manualmente el sensor.
  5) Ejecutar home() con el eje cerca del sensor y velocidad baja.
  6) Ejecutar move_to_mm(1), move_to_mm(5), move_to_mm(10).
  7) Medir desplazamiento real.
  8) Ajustar microsteps o parametros mecanicos si la distancia no coincide.

Velocidades iniciales recomendadas:

  - Ejes X/Y con banda: 5 a 20 mm/s para primeras pruebas.
  - Eje Z con tornillo: 1 a 5 mm/s para primeras pruebas.
  - HOME: usar velocidades menores que movimiento normal.

Antes de conectar motores reales:

  - Confirmar voltaje del driver.
  - Ajustar corriente limite del driver.
  - Verificar continuidad de bobinas del motor.
  - Revisar que no existan cortocircuitos.
  - Confirmar que ENABLE no active el driver inesperadamente.

Si el motor gira al reves:

  - Cambiar invert_direction de False a True o viceversa.
  - Verificar que home_direction siga apuntando hacia el sensor.
  - Repetir home() con velocidad baja.

Si el sensor HOME trabaja invertido:

  - Cambiar home_active_low.
  - Probar is_home_active() sin mover el eje.
  - Confirmar que el sensor activo devuelve True.

Como ajustar microsteps y steps_per_mm:

  - microsteps debe coincidir con el driver.
  - En banda, revisar dientes de polea y pitch.
  - En tornillo, revisar avance real por vuelta, no solamente paso de rosca.
  - Si el eje recorre menos de lo esperado, steps_per_mm podria ser demasiado
    alto.
  - Si el eje recorre mas de lo esperado, steps_per_mm podria ser demasiado
    bajo.

===============================================================================
18. LIMITACIONES DEL MODULO
===============================================================================

Este modulo tiene las siguientes limitaciones:

  - No implementa aceleracion.
  - No implementa desaceleracion.
  - No implementa perfil trapezoidal.
  - No implementa perfil S-curve.
  - No sincroniza varios ejes.
  - No calcula trayectorias XYZ.
  - No hace interpolacion lineal o circular.
  - No implementa closed-loop.
  - No lee encoder.
  - No detecta perdida de pasos.
  - No corrige backlash mecanico.
  - No compensa elasticidad de banda.
  - No compensa gravedad en Z.
  - No controla corriente del driver.
  - No configura drivers inteligentes por UART/SPI.
  - No implementa parada de emergencia global.
  - Requiere drivers externos.
  - Requiere HOME para que la posicion sea confiable.
  - Durante homing consulta el sensor entre bloques PIO, no en cada pulso.
  - Si se usa una velocidad demasiado alta, el arranque inmediato puede causar
    perdida de pasos.

Si se requiere movimiento avanzado, seria necesario agregar un planificador con:

  - aceleracion,
  - desaceleracion,
  - velocidad maxima dinamica,
  - sincronizacion de ejes,
  - control de jerk,
  - parada controlada,
  - comprobacion de sensores durante movimiento.

19. EJEMPLO CONCEPTUAL DE USO
===============================================================================

Ejemplo resumido para un eje X con banda GT2 y polea de 20 dientes:

  from objStepperAxis import BeltStepperAxis

  eje_x = BeltStepperAxis(
      pulley_teeth=20,
      belt_pitch_mm=2.0,
      name="X",
      step_pin=2,
      dir_pin=3,
      enable_pin=4,
      sm_id=0,
      motor_steps_per_rev=200,
      microsteps=16,
      speed_mm_s=10.0,
      max_speed_mm_s=80.0,
      min_position_mm=0.0,
      max_position_mm=220.0,
      home_pin=5,
      home_direction=-1,
      home_speed_mm_s=5.0,
      home_backoff_mm=2.0,
      invert_direction=False,
      enable_active_low=True,
      home_active_low=True,
  )

  if eje_x.home():
      eje_x.move_to_mm(50.0)
      eje_x.move_relative_mm(10.0)
      estado = eje_x.get_status()
      print(estado)
  else:
      print(eje_x.get_status()["error"])

Interpretacion:

  - Se crea un eje X con 80 steps/mm.
  - Se ejecuta home para fijar el cero.
  - Se mueve a la coordenada absoluta 50 mm.
  - Luego se mueve 10 mm adicionales hasta 60 mm.
  - Finalmente se consulta el estado.

===============================================================================
20. CONCLUSION
===============================================================================

El archivo objStepperAxis.py cumple el papel de modulo de control de eje individual para un sistema XYZ basado en Raspberry Pi Pico/RP2040 y MicroPython. Su diseño orientado a objetos permite crear ejes concretos de banda o tornillo reutilizando una logica comun de movimiento, homing, estado, errores y generacion de pulsos con PIO.

Dentro del sistema completo, este modulo es una capa intermedia entre la logica de aplicacion y el hardware de motores. Por debajo controla pines y StateMachine PIO; por encima ofrece metodos en milimetros que pueden ser usados por secuencias, controladores de movimiento, rutinas de calibracion o interfaces de usuario.

Su mayor fortaleza es simplificar el control basico de un eje con una interfaz clara. Su mayor limitacion es que trabaja con velocidad fija y no coordina varios ejes. Para movimientos XYZ avanzados se recomienda usar este modulo como base de eje y construir encima un controlador multieje con planificacion, aceleracion y sincronizacion.

===============================================================================
OBSERVACIONES Y MEJORAS RECOMENDADAS
===============================================================================

1) Agregar metodos is_busy() e is_homed()
   Aunque get_status() entrega esta informacion, seria practico incluir:

     is_busy()  -> state == STATE_MOVING or state == STATE_HOMING
     is_homed() -> is_homed_flag

2) Agregar metodo clear_error()
   Existe _clear_error() como metodo interno. Un metodo publico podria permitir
   limpiar errores de forma controlada despues de corregir una condicion.

3) Agregar aceleracion y desaceleracion
   La velocidad fija puede causar perdida de pasos en arranques bruscos. Un
   perfil trapezoidal mejoraria confiabilidad.

4) Agregar parada controlada
   stop() desactiva PIO abruptamente e invalida HOME. Seria util una parada con
   desaceleracion cuando no sea emergencia.

5) Mejorar homing con deteccion mas fina
   Actualmente el sensor HOME se consulta entre bloques PIO. Para maxima
   precision, podria implementarse lectura mas directa por PIO o bloques mas
   adaptativos.

6) Validar disponibilidad de sm_id
   El codigo asume que sm_id esta disponible. En sistemas con varios ejes se
   recomienda documentar o validar la asignacion de StateMachines.

7) Agregar timeouts explicitos
   Aunque home() limita la busqueda por recorrido maximo, wait_until_done() no
   tiene timeout. Un timeout podria evitar bloqueos si algo falla.

8) Agregar soporte para limites adicionales
   Podrian agregarse sensores de limite minimo/maximo independientes del sensor
   HOME.

9) Agregar calibracion asistida
   Un metodo para ajustar steps_per_mm a partir de distancia ordenada y distancia
   medida facilitaria la puesta a punto.

10) Agregar docstrings con tipos esperados
    Los docstrings actuales son claros, pero podrian ampliarse con tipos,
    unidades y rangos validos para facilitar mantenimiento.

11) Revisar el orden de validacion del constructor
    steps_per_mm se calcula antes de validar motor_steps_per_rev y microsteps.
    En la practica las clases derivadas validan su parte mecanica antes, pero
    podria ser mas claro validar motor_steps_per_rev y microsteps antes de usar
    esos valores en _calculate_steps_per_mm().

12) Considerar no usar lambda para IRQ interna
    En _run_steps_blocking() se registra una lambda que llama
    _mark_internal_move_done(). Funciona, pero para depuracion podria ser mas
    claro registrar directamente un metodo con firma compatible.

13) Agregar pruebas o ejemplos formales
    Seria recomendable incluir ejemplos separados para:
      - eje X/Y con banda,
      - eje Z con husillo,
      - homing,
      - movimiento absoluto,
      - movimiento relativo,
      - manejo de errores.
