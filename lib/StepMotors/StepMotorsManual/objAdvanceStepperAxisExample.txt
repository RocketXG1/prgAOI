1. TITULO

Archivo fuente analizado: objAdvanceStepperAxis.py
Archivo de ejemplos de instanciacion y uso para los objetos, clases y metodos principales del modulo objAdvanceStepperAxis.py.


2. INTRODUCCION

Este archivo contiene ejemplos practicos para aprender a instanciar y usar las clases disponibles en el modulo objAdvanceStepperAxis.py.

Los ejemplos estan orientados a un sistema XYZ con motores a pasos controlado por Raspberry Pi Pico / RP2040 usando MicroPython. El modulo permite controlar ejes lineales individuales mediante drivers externos STEP/DIR/ENABLE, sensores HOME opcionales, limites fisicos en milimetros y perfiles de movimiento constantes o trapezoidales.

Los valores usados en estos ejemplos son solo referencias de aprendizaje. Antes de probar en hardware real, se deben ajustar los pines, velocidades, aceleraciones, microsteps, limites, configuracion mecanica de polea/banda o tornillo/husillo, polaridad de ENABLE, polaridad del sensor HOME y sentido de giro segun el montaje real.

Los ejemplos sirven para aprender el uso de las clases del modulo, pero no reemplazan la calibracion ni las pruebas de seguridad del hardware. Se recomienda comenzar con movimientos cortos, velocidades bajas y el motor sin carga mecanica.


3. REQUISITOS PREVIOS

Modulos que deben existir en la Raspberry Pi Pico:

    - machine
      Usado para controlar pines GPIO mediante Pin.

    - rp2
      Usado para crear el programa PIO y las StateMachine del RP2040.

    - time
      Usado para esperas en milisegundos durante movimientos bloqueantes y HOME.

    - math
      Usado para calculos de perfiles trapezoidales o triangulares.

    - objAdvanceStepperAxis.py
      Debe estar cargado previamente en la Pico o en una ruta importable por MicroPython.

Requisitos de hardware:

    - Se requiere Raspberry Pi Pico, Raspberry Pi Pico W u otra placa compatible con RP2040 y MicroPython.

    - Se requieren drivers externos para motores a pasos con entradas STEP, DIR y ENABLE. Ejemplos: TB6600, TMC, DRV8825, A4988 o similares.

    - La Pico no debe alimentar directamente los motores. Los motores deben conectarse a drivers externos y a una fuente adecuada para los motores.

    - Los drivers y la Pico deben compartir GND comun.

    - Para usar home(), se requiere un sensor HOME o final de carrera conectado al pin configurado como home_pin.

    - Si no se configura home_pin, no se puede ejecutar home(). En ese caso el eje no quedara referenciado de forma real.

    - El archivo objAdvanceStepperAxis.py depende de machine, rp2, time y math. No depende de un controlador multi-eje para mover un solo eje, pero puede ser usado por un controlador externo del proyecto.

Notas sobre dependencias del proyecto:

    - Este archivo representa ejes individuales.

    - No contiene una clase MotionController.

    - Si se desea coordinar varios ejes, se debe usar otro modulo del proyecto o crear un bucle de control que llame update() en cada eje.

    - Los ejemplos de varios ejes de este documento instancian varios objetos de eje directamente, sin inventar una clase controladora que no existe en este archivo.


4. CLASES DISPONIBLES EN EL ARCHIVO

Clase: AdvancedStepperAxisBase

    Proposito:
        Es la clase base para un eje lineal avanzado con STEP, DIR, ENABLE y HOME. Administra estado, limites, conversion entre mm y pasos, rutina de HOME, perfiles de movimiento, PIO y metodos comunes.

    Cuándo conviene usarla:
        No conviene instanciarla directamente porque calculate_steps_per_mm() no esta implementado en la clase base. Conviene usarla como clase padre para crear tipos de ejes con otra mecanica de transmision.

    Parametros principales:
        name
        step_pin
        dir_pin
        enable_pin
        sm_id
        motor_steps_per_rev
        microsteps
        max_speed_mm_s
        acceleration_mm_s2
        deceleration_mm_s2
        min_speed_mm_s
        profile_segment_time_s
        min_position_mm
        max_position_mm
        home_pin
        home_direction
        home_speed_mm_s
        home_backoff_mm
        invert_direction
        enable_active_low
        home_active_low

    Metodos principales usados en los ejemplos:
        enable()
        disable()
        home()
        is_home_active()
        is_homed()
        get_position()
        get_status()
        validate_target(target_mm)
        calculate_minimum_time_s(distance_mm)
        create_trapezoidal_profile(distance_mm, total_time_s=None)
        create_constant_profile(distance_mm, speed_mm_s=None)
        start_move_to_mm(target_mm, profile_mode=PROFILE_TRAPEZOIDAL, total_time_s=None)
        move_to_mm(target_mm, profile_mode=PROFILE_TRAPEZOIDAL, total_time_s=None)
        start_move_relative_mm(distance_mm, profile_mode=PROFILE_TRAPEZOIDAL, total_time_s=None)
        move_relative_mm(distance_mm, profile_mode=PROFILE_TRAPEZOIDAL, total_time_s=None)
        update()
        wait_until_done()
        stop()

    Proposito:
        Representa un eje lineal accionado por polea y banda dentada.

    Cuándo conviene usarla:
        Conviene usarla en ejes X o Y de maquinas cartesianas cuando el movimiento lineal se obtiene con una banda dentada y una polea montada en el motor.

    Parametros principales:
        Todos los parametros comunes de AdvancedStepperAxisBase, mas:

    Metodos principales usados en los ejemplos:

        update()
        wait_until_done()
        get_status()
        stop()

Clase: AdvancedScrewStepperAxis

    Proposito:
        Representa un eje lineal accionado por tornillo, husillo o varilla roscada.

    Cuándo conviene usarla:
        Conviene usarla en ejes Z o en ejes donde se requiere mas fuerza, mayor resolucion o transmision por tornillo/husillo.

    Parametros principales:
        Todos los parametros comunes de AdvancedStepperAxisBase, mas:
        screw_lead_mm

    Metodos principales usados en los ejemplos:
        home()
        move_to_mm()
        move_relative_mm()
        start_move_to_mm()
        update()
        wait_until_done()
        get_status()
        stop()

Elementos publicos adicionales utiles:

    STATE_NOT_HOMED
    STATE_IDLE
    STATE_MOVING
    STATE_HOMING
    STATE_ERROR
    STATE_STOPPED
    PROFILE_CONSTANT
    PROFILE_TRAPEZOIDAL

    Estos valores ayudan a interpretar el estado del eje o seleccionar el tipo de perfil de movimiento.


5. VARIABLES Y PARAMETROS USADOS EN LOS EJEMPLOS

Listado de parametros importantes:

    name
        Nombre logico del eje.
        Ejemplos: "X", "Y", "Z".

    step_pin
        GPIO de la Pico conectado a la entrada STEP del driver.
        Ejemplos: 2, 6, 10.

    dir_pin
        GPIO conectado a la entrada DIR del driver.
        Ejemplos: 3, 7, 11.

    enable_pin
        GPIO conectado a la entrada ENABLE del driver.
        Ejemplos: 4, 8, 12.

    sm_id
        Identificador de la StateMachine PIO usada por el eje.
        Ejemplos: 0, 1, 2, 3.
        Cada eje que use PIO debe usar un sm_id diferente.

    motor_steps_per_rev
        Pasos completos del motor por vuelta.
        Ejemplo comun: 200 para un motor de 1.8 grados por paso.

    microsteps
        Configuracion de microstepping del driver.
        Ejemplos: 1, 2, 4, 8, 16, 32.
        Debe coincidir con los jumpers o configuracion real del driver.

    max_speed_mm_s
        Velocidad maxima permitida en mm/s.
        Ejemplos: 20.0, 50.0, 100.0.

    acceleration_mm_s2
        Aceleracion usada para perfiles trapezoidales o triangulares.
        Ejemplos: 50.0, 100.0, 300.0.

    deceleration_mm_s2
        Desaceleracion usada para perfiles trapezoidales o triangulares.
        Ejemplos: 50.0, 100.0, 300.0.

    min_speed_mm_s
        Velocidad minima usada para generar segmentos y frecuencia PIO segura.
        Ejemplos: 0.5, 1.0, 2.0.

    profile_segment_time_s
        Duracion aproximada de cada segmento del perfil avanzado.
        Ejemplos: 0.01, 0.02, 0.05.

    min_position_mm
        Limite minimo absoluto permitido para el eje.
        Ejemplo: 0.0.

    max_position_mm
        Limite maximo absoluto permitido para el eje.
        Ejemplos: 200.0, 300.0, 80.0.

    home_pin
        GPIO conectado al sensor HOME.
        Ejemplos: 5, 9, 13.
        Puede ser None si no se usara home(), aunque para operacion real se recomienda sensor HOME.

    home_direction
        Direccion de busqueda del HOME.
        Valores: -1 o 1.
        Use -1 si el HOME esta hacia el lado negativo del eje. Use 1 si esta hacia el lado positivo.

    home_speed_mm_s
        Velocidad de busqueda del sensor HOME.
        Ejemplos: 3.0, 5.0, 10.0.

    home_backoff_mm
        Distancia para retirarse del sensor despues del primer contacto, antes del segundo acercamiento lento.
        Ejemplos: 1.0, 2.0, 5.0.

    invert_direction
        Invierte la logica del pin DIR.
        Valores: True o False.
        Se usa cuando el eje se mueve al lado contrario del esperado.

    enable_active_low
        Indica si el driver se habilita con nivel bajo en ENABLE.
        Valores: True o False.
        Muchos drivers usan ENABLE activo en bajo, pero debe revisarse la hoja de datos.

    home_active_low
        Indica si el sensor HOME se considera activo cuando el pin lee 0.
        Valores: True o False.
        Con Pin.PULL_UP y un interruptor a GND normalmente se usa True.

    pulley_teeth
        Numero de dientes de la polea en un eje por banda.
        Ejemplos: 16, 20,  GT2 de 20 dientes.

    belt_pitch_mm
        Paso de la banda en mm por diente.
        Ejemplo comun: 2.0 para banda GT2.

    screw_lead_mm
        Avance lineal por vuelta del tornillo o husillo.
        Ejemplos: 2.0, 4.0, 8.0.

    profile_mode
        Tipo de perfil al mover.
        Valores usados por el modulo: PROFILE_CONSTANT o PROFILE_TRAPEZOIDAL.

    total_time_s
        Tiempo objetivo opcional para completar un movimiento.
        Ejemplos: None, 2.0, 5.0.
        Si se proporciona y es mayor al tiempo minimo calculado, el modulo reduce la velocidad pico para aproximar ese tiempo.


6. CONSIDERACIONES DE HARDWARE

Los pines usados en estos ejemplos son solo ejemplos. Deben cambiarse segun el cableado real de la Raspberry Pi Pico y de los drivers.

Cada eje debe usar un sm_id diferente si usa PIO. En RP2040 existen StateMachine PIO limitadas; no repita sm_id en dos ejes activos.

Los drivers de los motores deben compartir GND con la Pico. Sin GND comun, las senales STEP, DIR y ENABLE pueden ser inestables o no reconocerse.

La Pico no alimenta los motores. Los motores a pasos deben estar conectados a drivers externos y a una fuente de alimentacion adecuada para el voltaje y corriente del motor.

Los pines STEP, DIR y ENABLE de la Pico solo entregan senales logicas. No conecte un motor directamente a los GPIO.

Los sensores HOME deben probarse antes de mover el eje. Use is_home_active() para verificar que el estado cambia al presionar o activar el sensor.

Durante pruebas sin sensor HOME, se puede simular is_homed_flag=True solo en pruebas controladas y con movimientos cortos. Esto no debe usarse para operacion real, porque el eje no conoce su posicion fisica confiable.

Si el sensor HOME trabaja invertido, ajuste home_active_low. Con un interruptor normalmente abierto conectado a GND y pull-up interno, lo habitual es home_active_low=True. Si el sensor entrega nivel alto cuando esta activo, use home_active_low=False.


7. EJEMPLO 1 - INSTANCIACION MINIMA O BASICA

Objetivo:
    Crear un eje X por banda con parametros minimos razonables y mostrar una prueba de movimiento absoluto.

Advertencia:
    El metodo move_to_mm() exige que el eje este referenciado. En operacion real se debe ejecutar home() primero. En este ejemplo basico no se configura home_pin, por lo que se simula is_homed_flag=True solo para una prueba controlada, con el eje despejado y movimientos cortos.

Valores que deben cambiarse segun el hardware:
    step_pin, dir_pin, enable_pin, sm_id, microsteps, max_speed_mm_s, acceleration_mm_s2, deceleration_mm_s2, pulley_teeth, belt_pitch_mm, min_position_mm y max_position_mm.

Codigo completo:

    from objAdvanceStepperAxis import AdvancedBeltStepperAxis
    from objAdvanceStepperAxis import PROFILE_TRAPEZOIDAL

    # Crear un eje X accionado por polea y banda GT2.
    eje_x = AdvancedBeltStepperAxis(
        name="X",
        step_pin=2,
        dir_pin=3,
        enable_pin=4,
        sm_id=0,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=40.0,
        acceleration_mm_s2=80.0,
        deceleration_mm_s2=80.0,
        min_position_mm=0.0,
        max_position_mm=200.0,
        pulley_teeth=20,
        belt_pitch_mm=2.0
    )

    # Solo para prueba controlada sin HOME real.
    # No usar esta simulacion en operacion normal.
    eje_x.is_homed_flag = True
    eje_x.state = "IDLE"
    eje_x.current_position_mm = 0.0
    eje_x.current_position_steps = 0

    # Habilitar el driver externo.
    eje_x.enable()

    # Mover a posicion absoluta 20 mm desde el cero logico.
    eje_x.move_to_mm(20.0, profile_mode=PROFILE_TRAPEZOIDAL)

    # Leer estado y posicion final.
    estado = eje_x.get_status()
    print(estado)

    # Deshabilitar el driver si ya no se necesita mantener torque.
    eje_x.disable()

Explicacion linea por linea:

    - Se importa AdvancedBeltStepperAxis porque el eje usa polea y banda.
    - Se importa PROFILE_TRAPEZOIDAL para indicar que el movimiento usara aceleracion y desaceleracion segmentada.
    - Se crea eje_x con nombre X.
    - step_pin=2 conecta el GPIO 2 a STEP del driver.
    - dir_pin=3 conecta el GPIO 3 a DIR del driver.
    - enable_pin=4 conecta el GPIO 4 a ENABLE del driver.
    - sm_id=0 asigna la StateMachine PIO 0 al eje X.
    - motor_steps_per_rev=200 corresponde a un motor de 1.8 grados por paso.
    - microsteps=16 debe coincidir con la configuracion del driver.
    - max_speed_mm_s, acceleration_mm_s2 y deceleration_mm_s2 definen el comportamiento dinamico.
    - min_position_mm y max_position_mm definen el rango valido.
    - pulley_teeth y belt_pitch_mm permiten calcular los pasos por milimetro.
    - is_homed_flag se fuerza solo para prueba controlada sin HOME real.
    - enable() habilita el driver.
    - move_to_mm(20.0) mueve a 20 mm absolutos.
    - get_status() devuelve un diccionario con estado, posicion, limites y parametros.
    - disable() deshabilita el driver.


8. EJEMPLO 2 - INSTANCIACION CON PARAMETROS DE HOME

Objetivo:
    Crear un eje X por banda con sensor HOME, ejecutar home() y luego realizar un movimiento absoluto.

Comportamiento:
    home() busca el sensor en home_direction, se detiene cuando el sensor se activa, retrocede home_backoff_mm, vuelve a acercarse mas lento y finalmente fija la posicion actual como 0.0 mm.

Si el sensor trabaja invertido:
    - Si el sensor esta activo cuando el pin lee 0, use home_active_low=True.
    - Si el sensor esta activo cuando el pin lee 1, use home_active_low=False.
    - Si la direccion de busqueda se aleja del sensor, cambie home_direction de -1 a 1 o de 1 a -1.

Codigo completo:

    from objAdvanceStepperAxis import AdvancedBeltStepperAxis
    from objAdvanceStepperAxis import PROFILE_TRAPEZOIDAL

    eje_x = AdvancedBeltStepperAxis(
        name="X",
        step_pin=2,
        dir_pin=3,
        enable_pin=4,
        sm_id=0,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=50.0,
        acceleration_mm_s2=100.0,
        deceleration_mm_s2=100.0,
        min_speed_mm_s=1.0,
        min_position_mm=0.0,
        max_position_mm=250.0,
        home_pin=5,
        home_direction=-1,
        home_speed_mm_s=5.0,
        home_backoff_mm=3.0,
        home_active_low=True,
        pulley_teeth=20,
        belt_pitch_mm=2.0
    )

    # Verificar manualmente el sensor antes de mover.
    print("HOME activo al inicio:", eje_x.is_home_active())

    # Ejecutar rutina de referencia.
    if eje_x.home():
        print("HOME completado")
        eje_x.move_to_mm(30.0, profile_mode=PROFILE_TRAPEZOIDAL)
        print("Posicion actual:", eje_x.get_position())
    else:
        print("Error durante HOME:", eje_x.get_status())

Explicacion:

    - home_pin=5 indica el GPIO conectado al sensor HOME.
    - home_direction=-1 indica que el sensor esta hacia el lado negativo del eje.
    - home_speed_mm_s=5.0 usa una velocidad baja para buscar el sensor.
    - home_backoff_mm=3.0 retira el eje 3 mm antes del segundo acercamiento.
    - home_active_low=True es adecuado para muchos interruptores con pull-up y contacto a GND.
    - is_home_active() permite comprobar si el sensor cambia de estado.
    - home() debe completarse correctamente antes de mover.
    - move_to_mm(30.0) mueve a 30 mm absolutos desde el cero establecido por HOME.


9. EJEMPLO 3 - INSTANCIACION CON LIMITES Y DIRECCION INVERTIDA

Objetivo:
    Crear un eje Y por banda con limites fisicos y direccion invertida.

Cuándo se usa invert_direction:
    Se usa invert_direction=True cuando un movimiento positivo produce un desplazamiento fisico en sentido negativo o contrario al esperado. En lugar de cambiar cables del motor, se puede invertir la logica DIR desde software.

Qué ocurre si se pide un objetivo fuera de rango:
    validate_target() detecta que el destino esta fuera de min_position_mm y max_position_mm. El eje pasa a estado de error y move_to_mm() devuelve False.

Codigo completo:

    from objAdvanceStepperAxis import AdvancedBeltStepperAxis
    from objAdvanceStepperAxis import PROFILE_CONSTANT
    from objAdvanceStepperAxis import PROFILE_TRAPEZOIDAL

    eje_y = AdvancedBeltStepperAxis(
        name="Y",
        step_pin=6,
        dir_pin=7,
        enable_pin=8,
        sm_id=1,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=60.0,
        acceleration_mm_s2=120.0,
        deceleration_mm_s2=120.0,
        min_position_mm=0.0,
        max_position_mm=180.0,
        home_pin=9,
        home_direction=-1,
        home_speed_mm_s=5.0,
        home_backoff_mm=2.0,
        invert_direction=True,
        enable_active_low=True,
        home_active_low=True,
        pulley_teeth=20,
        belt_pitch_mm=2.0
    )

    if not eje_y.home():
        print("No se pudo hacer HOME en Y")
        print(eje_y.get_status())
    else:
        # Movimiento valido dentro del rango 0 a 180 mm.
        resultado_1 = eje_y.move_to_mm(100.0, profile_mode=PROFILE_TRAPEZOIDAL)
        print("Movimiento a 100 mm:", resultado_1)

        # Movimiento absoluto a 70 mm. Esto va a 70, no suma 70.
        resultado_2 = eje_y.move_to_mm(70.0, profile_mode=PROFILE_CONSTANT)
        print("Movimiento a 70 mm:", resultado_2)

        # Movimiento invalido: 250 mm supera max_position_mm=180.
        resultado_3 = eje_y.move_to_mm(250.0)
        print("Movimiento fuera de rango:", resultado_3)
        print("Estado despues del intento:", eje_y.get_status())

Explicacion:

    - min_position_mm=0.0 y max_position_mm=180.0 definen el rango seguro.
    - invert_direction=True invierte el nivel logico aplicado al pin DIR.
    - move_to_mm(100.0) intenta ir a la posicion absoluta 100 mm.
    - move_to_mm(70.0) intenta ir a la posicion absoluta 70 mm; no agrega 70 mm a la posicion actual.
    - move_to_mm(250.0) falla porque 250 mm esta fuera del limite maximo.
    - El estado resultante incluye el mensaje de error en el campo error de get_status().


10. EJEMPLO 4 - USO CON VARIOS EJES

Objetivo:
    Crear tres ejes para un sistema XYZ:
        X por banda/polea.
        Y por banda/polea.
        Z por tornillo/husillo.

Nota importante:
    Este archivo no contiene un MotionController. Por eso, el ejemplo instancia directamente los ejes y usa un pequeno bucle para actualizar movimientos no bloqueantes. Si el proyecto tiene un controlador externo, ese controlador podria encargarse de llamar update() en cada eje.

Movimiento absoluto:
    move_to_mm(150.0) significa ir a la posicion absoluta 150 mm.
    Luego move_to_mm(70.0) significa ir a la posicion absoluta 70 mm.
    No significa sumar 70 mm al movimiento anterior.

Codigo completo:

    import time
    from objAdvanceStepperAxis import AdvancedBeltStepperAxis
    from objAdvanceStepperAxis import AdvancedScrewStepperAxis
    from objAdvanceStepperAxis import PROFILE_TRAPEZOIDAL

    eje_x = AdvancedBeltStepperAxis(

        step_pin=2,
        dir_pin=3,
        enable_pin=4,
        sm_id=0,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=80.0,
        acceleration_mm_s2=150.0,
        deceleration_mm_s2=150.0,
        min_position_mm=0.0,
        max_position_mm=300.0,
        home_pin=5,
        home_direction=-1,
        home_speed_mm_s=8.0,
        home_backoff_mm=3.0,
        pulley_teeth=20,
        belt_pitch_mm=2.0
    )

    eje_y = AdvancedBeltStepperAxis(
        name="Y",
        step_pin=6,
        dir_pin=7,
        enable_pin=8,
        sm_id=1,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=80.0,
        acceleration_mm_s2=150.0,
        deceleration_mm_s2=150.0,
        min_position_mm=0.0,
        max_position_mm=250.0,
        home_pin=9,
        home_direction=-1,
        home_speed_mm_s=8.0,
        home_backoff_mm=3.0,
        pulley_teeth=20,
        belt_pitch_mm=2.0
    )

    eje_z = AdvancedScrewStepperAxis(
        name="Z",
        step_pin=10,
        dir_pin=11,
        enable_pin=12,
        sm_id=2,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=15.0,
        acceleration_mm_s2=40.0,
        deceleration_mm_s2=40.0,
        min_position_mm=0.0,
        max_position_mm=80.0,
        home_pin=13,
        home_direction=-1,
        home_speed_mm_s=2.0,
        home_backoff_mm=1.0,
        screw_lead_mm=8.0

    # Referenciar cada eje. En una maquina real, verificar espacio libre antes.
    for eje in (eje_x, eje_y, eje_z):
        if not eje.home():
            print("Error haciendo HOME en", eje.name, eje.get_status())
            eje.stop()

    # Movimiento absoluto bloqueante eje por eje.
    eje_x.move_to_mm(150.0, profile_mode=PROFILE_TRAPEZOIDAL)
    eje_y.move_to_mm(100.0, profile_mode=PROFILE_TRAPEZOIDAL)
    eje_z.move_to_mm(20.0, profile_mode=PROFILE_TRAPEZOIDAL)

    # Ir a otra posicion absoluta. X va a 70 mm, no suma 70 mm.
    eje_x.move_to_mm(70.0, profile_mode=PROFILE_TRAPEZOIDAL)

    # Ejemplo de arranque no bloqueante de los tres ejes.
    eje_x.start_move_to_mm(120.0, profile_mode=PROFILE_TRAPEZOIDAL)
    eje_y.start_move_to_mm(150.0, profile_mode=PROFILE_TRAPEZOIDAL)
    eje_z.start_move_to_mm(10.0, profile_mode=PROFILE_TRAPEZOIDAL)

    # Bucle simple para permitir que cada eje avance sus segmentos.
    while eje_x.is_busy() or eje_y.is_busy() or eje_z.is_busy():
        eje_x.update()
        eje_y.update()
        eje_z.update()
        time.sleep_ms(1)

    print("Estado X:", eje_x.get_status())
    print("Estado Y:", eje_y.get_status())
    print("Estado Z:", eje_z.get_status())

Explicacion:

    - X e Y usan AdvancedBeltStepperAxis porque son ejes por banda.
    - Z usa AdvancedScrewStepperAxis porque es un eje por tornillo/husillo.
    - sm_id es diferente para cada eje: 0, 1 y 2.
    - Cada eje usa pines STEP, DIR, ENABLE y HOME diferentes.
    - Primero se ejecuta home() en cada eje.
    - Los primeros move_to_mm() son bloqueantes y se ejecutan uno por uno.
    - Luego se usan start_move_to_mm() y update() para iniciar movimientos no bloqueantes en varios ejes.
    - Este bucle no garantiza sincronizacion geometrica perfecta; solo permite que cada eje avance sus perfiles. Para coordinacion real puede requerirse un controlador superior.


11. EJEMPLO 5 - USO AVANZADO O CASO COMPLETO

Objetivo:
    Mostrar un flujo completo con HOME, perfil trapezoidal, calculo de tiempo minimo, movimiento absoluto, movimiento relativo, movimiento no bloqueante con update(), lectura de status y stop().

Codigo completo:

    import time
    from objAdvanceStepperAxis import AdvancedScrewStepperAxis
    from objAdvanceStepperAxis import PROFILE_CONSTANT
    from objAdvanceStepperAxis import PROFILE_TRAPEZOIDAL

    eje_z = AdvancedScrewStepperAxis(
        name="Z",
        step_pin=10,
        dir_pin=11,
        enable_pin=12,
        sm_id=2,
        motor_steps_per_rev=200,
        microsteps=16,
        max_speed_mm_s=12.0,
        acceleration_mm_s2=30.0,
        deceleration_mm_s2=30.0,
        min_speed_mm_s=0.5,
        profile_segment_time_s=0.02,
        min_position_mm=0.0,
        max_position_mm=60.0,
        home_pin=13,
        home_direction=-1,
        home_speed_mm_s=1.5,
        home_backoff_mm=1.0,
        invert_direction=False,
        enable_active_low=True,
        home_active_low=True,
        screw_lead_mm=8.0
    )

    # 1. Revisar sensor HOME antes de mover.
    print("Sensor HOME activo:", eje_z.is_home_active())

    # 2. Hacer HOME real.
    if not eje_z.home():
        print("Fallo HOME Z:", eje_z.get_status())
        eje_z.stop()
    else:
        print("HOME Z correcto")

        # 3. Calcular tiempo minimo estimado para 30 mm con la configuracion actual.
        tiempo_minimo = eje_z.calculate_minimum_time_s(30.0)
        print("Tiempo minimo estimado para 30 mm:", tiempo_minimo)

        # 4. Movimiento absoluto con perfil trapezoidal.
        eje_z.move_to_mm(30.0, profile_mode=PROFILE_TRAPEZOIDAL)
        print("Despues de ir a 30 mm:", eje_z.get_status())

        # 5. Movimiento relativo: subir o bajar 5 mm desde la posicion actual.
        eje_z.move_relative_mm(-5.0, profile_mode=PROFILE_TRAPEZOIDAL)
        print("Despues de movimiento relativo -5 mm:", eje_z.get_position())

        # 6. Movimiento absoluto con velocidad constante.
        eje_z.move_to_mm(10.0, profile_mode=PROFILE_CONSTANT, total_time_s=3.0)
        print("Despues de ir a 10 mm en perfil constante:", eje_z.get_status())

        # 7. Movimiento no bloqueante con tiempo objetivo.
        eje_z.start_move_to_mm(40.0, profile_mode=PROFILE_TRAPEZOIDAL, total_time_s=6.0)
        while eje_z.is_busy():
            eje_z.update()
            time.sleep_ms(1)

        print("Despues de movimiento no bloqueante:", eje_z.get_status())

        # 8. Parada manual al final de la prueba.
        # stop() deshabilita el driver y marca HOME como no confiable.
        eje_z.stop()
        print("Despues de stop:", eje_z.get_status())

Flujo completo explicado:

    - Se crea un eje Z con transmision por tornillo/husillo.
    - Se revisa el estado del sensor HOME con is_home_active().
    - Se ejecuta home() para establecer el cero real.
    - calculate_minimum_time_s(30.0) estima el tiempo minimo teorico para una distancia.
    - move_to_mm(30.0) realiza un movimiento absoluto con perfil trapezoidal.
    - move_relative_mm(-5.0) se desplaza -5 mm desde la posicion actual.
    - move_to_mm(10.0, PROFILE_CONSTANT, total_time_s=3.0) usa perfil constante y calcula una velocidad aproximada para cubrir la distancia en 3 segundos, respetando min_speed_mm_s y max_speed_mm_s.
    - start_move_to_mm(40.0, total_time_s=6.0) inicia un movimiento no bloqueante.
    - update() se llama repetidamente para avanzar de segmento en segmento.
    - get_status() permite observar estado, posicion, perfil activo, pasos por mm y otros datos.
    - stop() detiene, deshabilita el driver y marca el HOME como no confiable.

15. ERRORES COMUNES AL INSTANCIAR

    - Repetir sm_id en dos ejes activos.
      Cada eje con PIO debe usar una StateMachine diferente.

    - Usar pines repetidos.
      No use el mismo GPIO para STEP, DIR, ENABLE o HOME de ejes distintos, salvo que el diseno electrico lo justifique y se entienda completamente.

    - No compartir GND.
      La Pico y los drivers deben compartir tierra para que las senales logicas sean validas.

    - Configurar mal microsteps.
      Si el software usa microsteps=16 pero el driver esta configurado en 8, las distancias reales seran incorrectas.

    - No hacer HOME antes de mover.
      El modulo exige is_homed_flag=True antes de mover. En operacion real, esto debe lograrse con home().

    - Poner limites incorrectos.
      Si max_position_mm es mayor que el recorrido real, el eje podria chocar mecanicamente.

    - Confundir movimiento absoluto con relativo.
      move_to_mm(70.0) va a 70 mm absolutos. move_relative_mm(70.0) suma 70 mm a la posicion actual.

    - Usar una velocidad demasiado alta.
      Puede causar perdida de pasos, vibracion, ruido, falta de torque o bloqueo del motor.

    - Invertir mal el sensor HOME.
      Si home_active_low no coincide con el sensor, home() puede creer que el sensor esta activo cuando no lo esta, o no detectarlo nunca.

    - No configurar correctamente polea, banda o tornillo.
      En ejes por banda, pulley_teeth y belt_pitch_mm deben coincidir con la mecanica real. En ejes por tornillo, screw_lead_mm debe ser el avance real por vuelta.

    - Usar enable_active_low incorrecto.
      Algunos drivers habilitan con nivel bajo y otros con nivel alto. Si se configura mal, el motor puede quedar siempre deshabilitado o siempre energizado.

    - Usar home_speed_mm_s mayor que max_speed_mm_s.
      El constructor valida que home_speed_mm_s sea mayor que cero y menor o igual que max_speed_mm_s.

    - Dar valores cero o negativos en parametros criticos.
      motor_steps_per_rev, microsteps, max_speed_mm_s, acceleration_mm_s2, deceleration_mm_s2, min_speed_mm_s, profile_segment_time_s, pulley_teeth, belt_pitch_mm y screw_lead_mm deben ser mayores que cero.

17. CONCLUSION

Los ejemplos de este archivo muestran como usar objAdvanceStepperAxis.py para crear ejes lineales avanzados con motores a pasos en Raspberry Pi Pico / MicroPython.

Se recomienda empezar con el ejemplo mas basico para entender los parametros del constructor. Luego se debe avanzar al ejemplo con HOME real, despues agregar limites e inversion de direccion si hace falta, y finalmente probar varios ejes o flujos avanzados con perfiles trapezoidales, movimientos relativos, update() y status.

Todos los valores deben calibrarse segun el hardware real: pines GPIO, drivers, microsteps, poleas, bandas, tornillos, sensores HOME, velocidades, aceleraciones, limites mecanicos y polaridades electricas.

Para operacion real, no se debe depender de is_homed_flag simulado. Siempre que sea posible, use sensores HOME reales, limites seguros, velocidades bajas en las primeras pruebas y un paro de emergencia fisico.
